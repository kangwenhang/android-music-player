# 科帕奇音乐播放器

专为 **安卓 4.2.2(API 17)** 车机设计的音乐播放器(科帕奇 2015 款改装车机,7 寸 1024×600 横屏)。

## 功能特性

### 播放核心
- 本地音乐扫描与播放(MediaStore + MediaPlayer)
- **Navidrome 服务器同步**(Subsonic API,同步服务器歌曲列表到本地)
- **飞牛音乐(FN Music)数据源**:`FnMusicApi` 实现全套接口(登录 / 专辑 / 曲目 / 艺人 / 串流 / 封面 / 歌词)
- **FN ID 直接登录**:服务器地址栏可直接填 FN ID(如 `k495378412`),由 `FnIdResolver` 解析出
  局域网 / IPv6 / 公网 / 中继地址并自动择优;中继链路自动带 `Cookie: mode=relay` 并手动跟进 302
- **启动默认进入云端列表**:每次开 app 固定进云端(不再沿用上次退出时的模式),避免出现空列表;
  会话内仍可自由切换本地/云端
- **连点切换防抖**:连续点击本地/云端时,250ms 窗口内的连发点击只按最终目标重建一次列表
- 播放模式记忆:顺序 / 单曲循环 / 随机,状态自动保存
- **开机自动播放**(可开关,记忆上次播放歌曲和进度,断点续播)
- 播放模式:顺序 / 单曲循环 / 随机
- 后台播放 + 通知栏控制
- 方向盘媒体按键响应

### 搜索
- 实时搜索(本地即时过滤,网络防抖搜索)
- 按歌曲名和歌手名匹配,精准过滤

### 均衡器
- 系统 Equalizer,5 段频段调节
- **内置预设**:关闭、流行、摇滚、爵士、古典、重低音
- **自定义预设**:保存/删除个人调节方案
- **单曲 EQ 绑定**:为每首歌绑定独立均衡器设置,切歌自动恢复
- 底部控制栏 EQ 快捷按钮,实时显示当前模式

### 界面与歌词
- **歌词叠加在封面上**(封面放大模糊作为底色背景,歌词在上)
- 加大歌词字体,当前行 28px / 其他行 22px
- **VBR 歌词同步**:混合位置追踪(系统时钟+MediaPlayer),自动校正 VBR MP3 位置偏差
- **歌词偏移手动调整**:长按歌词区逐 200ms 微调,设置自动保存,每首歌独立
- **歌词来源(按优先级依次尝试,见 `MusicService.loadLyrics`)**:
  1. **内嵌标签**:`MediaMetadataRetriever` 取 ID3 `LYRICS` / `DESCRIPTION`,读不到则自解析 ID3 `USLT` 帧
  2. **同名 .lrc 文件**:音频同目录下与主名完全一致的 `.lrc`(UTF-8 优先,失败回退 GBK)
  3. **歌词缓存**:`LyricCache` 按 streamId 缓存的 `.lrc`(断网可用)
  4. **网络兜底**:服务器 API 按 songId / 歌手+歌名取词,成功后再写回本地
  5. **公开歌词源**:服务器也没词时,按歌手+歌名查 `lrclib.net`(免费、无需 key),
     取到带时间轴的 LRC 就写回同名 `.lrc`,下次直接本地读取
  - 本地歌曲只要**本地有文件**就走前两步优先取本地歌词,断网也能正常显示
  - 第 5 级需要车机能访问外网;外网不通时静默跳过,不影响播放
    (连续 2 次网络异常后进入 10 分钟冷却,不会每切一首歌都白等超时)
  - 想彻底关掉第 5 级:把 `LrclibClient.ENABLED` 改成 `false`
- 禁用列表切换动画,减少视觉跳动感
- 粉橙渐变 APP 图标,圆角矩形设计

### 车机适配优化
- **电阻屏优化**:大按钮(64/80dp)+ 大间距 + 大字体,便于触控
- **本地列表缓存秒开**:歌曲列表持久化到本机,打开即显示,不读 U 盘
- **点击歌曲才读 U 盘**:列表从缓存加载,仅播放时才访问 U 盘文件
- **手动刷新列表**:设置中新增"刷新歌曲列表",U 盘增删歌曲后手动更新
- **三级封面缓存**:内存 LruCache(28MB,5000+张)→ 内部存储磁盘缓存(200MB)→ U 盘/网络
- **不滚动时全量载入内存**:停止滑动后后台把磁盘缓存全部载入内存,之后滚动零磁盘 IO
- **滚动性能深度优化**:滑动时暂停磁盘 IO 和歌词更新,停止后补加载,消除卡顿
- **播放状态同步**:从桌面返回时自动同步当前播放歌曲,解决自动切歌后显示不同步
- **收藏/搜索高亮**:过滤后只高亮当前播放歌曲,不在列表中则清除高亮
- **收藏按来源分开(云端 / 本地各自独立)**:
  - **云端模式**:收藏夹取**服务器收藏列表**(Navidrome `getStarred2` / 飞牛 `favorite-track/list`),
    点爱心收藏时同步写回服务器(跨设备同步);取不到时自动退回本机收藏
  - **本地模式**:收藏夹取本机 `FavoriteManager`(SharedPreferences,按 `net_{streamId}` /
    `local_{路径}` 记录),纯离线
  - 切换本地/云端时自动重置收藏夹状态,不会用服务器 ID 去过滤本地歌(否则列表变空)
  - **点爱心是"乐观更新",列表立刻就动**:本地改 ID 集合 + 立即重过滤,服务器同步在后台跑;
    只有同步失败才回滚(以服务器真实状态重拉一次)并提示"服务器同步失败,仅本机"
    (以前要等服务器收藏列表整个重拉一遍才刷新,一次网络往返下来就是"点了半天没反应")
  - **反复进出收藏夹是秒开**:本次会话已拉过就用现有 ID 集合重过滤,不再每进一次走一轮网络
  - 飞牛写端点未公开,首次成功后**记住**该端点,之后每次只发一个请求
    (否则要逐个试 3 个候选,最坏 3×(10s+15s))
  - **退出收藏夹一定切回全部歌曲**:顶部计数是**同步**刷的、列表是**异步**刷的,
    两者会错位 —— 出现过"计数已变成共 810 首、列表还是收藏那几行"。
    根因是分批补加载 `ensureLoaded()` 里那句无条件自增把在途过滤结果整包作废了。
    现在把两个代次拆开:`filterGeneration` 只表示"有没有更新的过滤请求",
    新增 `dataVersion` 表示"列表被结构性改动过";后者变化时**按当前列表重算一次 Diff
    再套用**,而不是丢掉结果。模式切换走 `force` 通道不被 120ms 防抖吞掉,
    并带 500ms 自愈兜底(发现真没切过来就再强制过滤一次,同时写诊断日志)
- **导航播报自动压低音量**:AudioFocus 支持,导航播报时音乐自动降低音量,播报结束恢复
- **应用内更新**:检测新版本并下载安装,带进度条显示
- **启动优化**:延迟重型初始化,避免白屏
- **网络歌曲缓存优先加载**:切换网络模式秒开,后台静默更新
- 全屏沉浸模式:隐藏状态栏和虚拟导航键
- 横屏锁定,适配 1024×600 分辨率
- 设置中显示屏幕分辨率与 DPI 检测

## 目录结构(本地 / 云端隔离)

设置里只需要配置一个**音乐文件根目录**(默认 `外部存储/Music`),两类歌曲自动隔离、互不串味:

```
<音乐根目录>/
├── 本地歌曲/          ← 本地列表的数据来源,首次访问自动创建
└── <服务器子目录>/     ← 云端歌曲缓存目录,按服务器自动命名
                         (飞牛 → "飞牛";Navidrome → "na"+3位哈希)
```

- **本地歌曲目录不再需要单独设置**:固定派生为 `根目录/本地歌曲` 并自动创建,
  把歌拷进去即可在本地列表里看到(本地模式的空列表提示也会引导你把歌放这里)
- 云端歌曲按服务器分子目录存放,换服务器不会互相覆盖

## 黑屏 / 卡顿排查(诊断日志）

黑屏、"过一会儿黑一下、点一下又亮"这类问题在车机上完全看不到线索（没有 adb、没有 logcat），
于是把关键事件都落到 **音乐根目录 `download_debug.log`**。复现后把文件拷出来，按下面三条对号即可定位：

| 日志里看到 | 结论 | 处理 |
| --- | --- | --- |
| `[屏幕] 系统广播 熄屏` + `[生命周期] onPause \| 屏幕=灭` | 系统把屏幕关了（息屏超时 / 电源策略） | App 侧已加两层常亮（见下）；另把系统「设置 → 显示 → 休眠」设为"永不" |
| 屏幕=亮 + `[主线程] 卡顿 Xms` | App 自己卡住了主线程，窗口在这段时间画不出新帧 | 按日志里的耗时点排查同步重活（本项目历史两次黑屏都是这个原因） |
| 屏幕=亮 + 无卡顿行 + 堆正常 | 显示 / 合成层没合成画面（模拟器宿主 GPU、车机 SurfaceFlinger） | App 改不了：换设备或关掉模拟器硬件加速再验 |
| 又一次 `==== download_debug.log 开始记录 ====` | 进程被杀后重启，这才是真正的"内存回收" | 配合上面 `[内存] 系统要求释放内存 level=…` 看是哪个档位触发 |

日志采集点：
- `[屏幕]` — `ACTION_SCREEN_OFF / ON / USER_PRESENT` 广播（注册在 Application 上，任何页面都不会漏）
- `[内存]` — `Application.onTrimMemory / onLowMemory`（本项目没有任何主动回收逻辑，这两行只做取证）
- `[主线程]` — `MainThreadWatchdog`：后台线程每 5s 往主线程丢一个空任务量往返耗时，只记超过 1.5s 的
- `[生命周期]` — 主界面 `onResume / onPause`，带当前屏幕状态与堆占用
- 播放/下载相关的 `[界面]`、下载失败原因同样落在这个文件

### 屏幕常亮（两层保障）

1. **`FLAG_KEEP_SCREEN_ON`**——四个 Activity 的 `onCreate` / `onResume` / `onWindowFocusChanged`
   都会重新补一次；不需要权限，Activity 不可见时系统自动失效，无泄漏风险
2. **`ScreenOnKeeper`**——前台持有 `SCREEN_BRIGHT_WAKE_LOCK`（`onResume` 申请 / `onPause` 释放，
   多 Activity 切换用引用计数）。加这一层是因为窗口标志依赖 WindowManager 的 hold-screen 记账
   （同一时刻只有一个窗口被认定持有屏幕），息屏 / 解锁 / 系统弹窗插进来之后偶尔会没被重新认定，
   表现为"标志明明加着，过一会儿还是黑屏"；直接持锁绕开这层。
   只在界面前台时持锁，**不会**出现"挂着导航在后台听歌导致屏幕永不熄灭"。

## Navidrome 配置

1. 打开 App,点击右上角"设置"按钮
2. 选择"服务器设置"
3. 输入服务器地址(如 `http://192.168.1.100:4533`)、用户名和密码
4. 点击"测试连接"验证,然后"保存"
5. 点击"同步歌曲"按钮,将服务器歌曲列表同步到本地

### v5.7.1 更新内容

- **自解析 ID3 内嵌歌词(车机读 USLT 的兜底)**:车机安卓 4.2.2 的 `MediaMetadataRetriever`
  取不到 `METADATA_KEY_LYRICS`(文件里明明有 USLT 却返回 null),而本地歌没有 streamId,
  歌词缓存与网络兜底都用不上。`EmbeddedLyricsExtractor` 新增自解析:系统读不到时直接解析
  ID3v2 的 USLT 帧(v2.2/2.3/2.4、ISO-8859-1 / UTF-16 / UTF-16BE / UTF-8、反同步字节还原、
  UTF-8 乱码回退 GBK),只读标签区不读整个文件,跑在歌词加载的后台线程
- 实测:本地 10 首歌的 USLT 全部解析成功(43~138 行),不再需要手工导出 `.lrc`
  (已导出的 `.lrc` 保留也无妨,它更靠后才会被用到,可当备份)
- **公开歌词源兜底(新增 `LrclibClient`)**:服务器(飞牛 / Navidrome)也取不到词时,
  按歌手+歌名到 `lrclib.net` 再试一次 —— 免费、无需 API key,优先返回带时间轴的 LRC。
  三级查询:精确匹配(带时长)→ 忽略时长 → 搜索接口(按时长挑最接近的版本,
  避免「我知道」250s 与 214s 两个版本拿错词)。取到后写回同名 `.lrc` / 歌词缓存
- **不影响播放的三重保护**:① 三级查询共享 8 秒总预算,不会占死歌词加载线程
  (那是单线程池,占死了后面切歌的歌词会全排队);② 连续 2 次网络异常进入 10 分钟冷却
  (404 不算异常 —— 那是链路通、库里没这首);③ 单次响应上限 256KB,防止车机小堆被吃
- 走 `TlsCompat.open()`:实测 lrclib 在 TLS 1.0 下返回 503(Cloudflare 拒绝),
  必须 TLS 1.1+;而安卓 4.2.2 默认只开 SSLv3/TLSv1.0,不套兼容层会直接握手失败
- 实测中文歌命中率良好(「我知道/BY2」「稻香/周杰伦」「月牙湾/F.I.R.」均命中)

### v5.7 更新内容(正式版)

- **接入飞牛音乐(FN Music)数据源**:新增 `FnMusicApi`,支持 `user/password-login`、`album/list`、`track/list`、`artist/list`、`track/stream`、`static/cover`、`lyric/list` 全套接口
- **FN ID 直接登录**:服务器地址栏可直接填 FN ID(如 `k495378412`),由 `FnIdResolver` 通过官方查询接口解析出局域网 / IPv6 / 公网 / 中继地址并自动择优
- **官方中继支持**:中继链路自动带 `Cookie: mode=relay`,并手动跟进 302(自动重发该 Cookie);已实测可通过 `k495378412.5ddd.com` 完成登录与取歌
- **歌曲名按字母/拼音排序**:新增 `MusicTitleComparator`,先用 `PinyinUtils` 按首字母分组,组内再用 ICU Collator 细分
- **拼音首字母算法**:`PinyinUtils` 基于 GB2312 一级汉字区位码(不依赖设备 ICU 数据),结果确定、不随系统变化;已离线验证 79/82 用例正确,生僻字与繁体归入 `#`
- **右侧 A-Z 快速索引条**:新增 `SideIndexBar` 自定义 View,A~Z 加 `#`,无歌字母自动置灰并按最近邻跳转;按下/拖动时列表跳转到该字母首曲,居中显示大字母提示,抬手 600ms 后消失
- 搜索 / 收藏夹过滤时索引条自动隐藏(此时列表不是全量排序结果,字母索引会错位)
- 列表右侧预留 34dp 给索引条,避免遮挡曲目
- **本地歌曲目录改为固定派生**:设置页移除"本地模式目录"配置项,本地目录固定为 `音乐根目录/本地歌曲`
  并自动创建,与云端歌曲(根目录/服务器子目录)天然隔离,用户只需配置一个音乐根目录
- **启动默认进入云端列表**:不再沿用上次退出时的模式,避免出现"一开 app 就是空列表"
- **修复连点本地/云端闪退**:连点会触发多次 815 首全量重建,持续高分配把主线程 GC 卡到数百毫秒直至进程崩溃;
  新增 250ms 防抖(连发点击只按最终目标重建一次)+ 目标模式短路(切回原模式则零重建)
- **云端列表解析写穿缓存**:播放自动缓存完成后原实现会作废内存缓存,导致下次切换从 2ms 内存命中
  退化成 ~590ms 重新解析;现改为保存后直接刷新内存缓存
- **全局崩溃堆栈落盘**:车机不便接 adb,未捕获异常会先写入 `音乐根目录/crash_log.txt` 再交回系统
- **关闭诊断日志**:`cache_debug.log` / `perf_log.txt` 由 `CacheDebugLog.ENABLED`、`PerfLogger.ENABLED`
  常量控制(当前均关闭),需要排查时改回 `true` 重新构建即可,调用点无需改动
